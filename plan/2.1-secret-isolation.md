# Phase 2.1 — Keep agents away from `.env` (container isolation)

**Goal:** factory agents never see orchestrator secrets. Each agent session runs in an
ephemeral Docker container that can only see its worktree + the LLM provider key it
needs. `.env` (TRELLO_*, DISCORD_*, GITHUB_TOKEN, WEBHOOK_SECRET) stays on the host,
in the orchestrator process only.

**Decision (confirmed):** container isolation — one `docker run` per agent session.
This is what pi's security docs recommend as the strongest practical boundary:
"Entirely inside a container, virtual machine, or sandbox — host files and processes
that you do not expose to the environment."

## Threat model (what leaks today)

| Vector | Today | After 2.1 |
|---|---|---|
| `process.env` | In-process `createAgentSession` inherits the full orchestrator env; agent can `printenv`/`env` via its bash tool | Container gets only an allowlisted env (LLM key, PATH, HOME) |
| Files | Agent runs as the factory OS user; can `cat <repo>/.env` by absolute path | Only the worktree dir is bind-mounted; host FS is invisible |
| Git worktree | `.env` is untracked so worktrees don't contain it (good — keep it that way, tested) | Same, plus asserted in tests |
| Network | Agent can reach anything | Unchanged (accepted risk, documented); optional proxy egress later |

**Boundary rule:** the container is the trust boundary. Everything on the host
(orchestrator, `.env`, Trello/GitHub/Discord clients, push + PR creation) stays outside.

## Architecture

```
host (orchestrator, keeps ALL secrets)
├── worker/queue.ts        unchanged
├── worker/runner.ts       agent step becomes: runAgentInContainer(worktreeDir, prompt, onEvent)
└── after agent exits: host does `git push` + Octokit PR (needs GITHUB_TOKEN — never in container)

container (ephemeral, per agent run)
├── image: factory-agent (node:22-slim + pi CLI, non-root user)
├── mounts: <worktree>:/work   (only)
├── env:    LLM provider key + PATH + HOME   (only)
└── cmd:    pi --mode json --no-approve "<prompt>"   → NDJSON events on stdout
```

Event streaming to Discord is preserved: pi's JSON mode writes newline-delimited
session events on stdout; the host parses them and maps
`tool_execution_start`/text deltas to the existing progress embeds (same mapping the
in-process `session.subscribe` did).

## Steps

- [ ] **1. Agent image.** `deploy/docker/factory-agent.Dockerfile`:
  ```dockerfile
  FROM node:22-slim
  RUN npm i -g @earendil-works/pi-coding-agent
  RUN useradd -m agent
  WORKDIR /work
  USER agent
  ENTRYPOINT ["pi"]
  ```
  Plus `deploy/docker/build.sh` (`docker build -t factory-agent ...`) and a CI job /
  VPS deploy step that builds it.
- [ ] **2. Env allowlist builder** — `src/agent/env.ts` (pure, unit-testable):
  ```ts
  const PROVIDER_KEYS = ["ANTHROPIC_API_KEY","OPENAI_API_KEY","GEMINI_API_KEY",
                         "GROQ_API_KEY","OPENROUTER_API_KEY","MISTRAL_API_KEY"];
  export function buildAgentEnv(): Record<string,string> // PATH, HOME + set provider keys
  ```
  Only provider keys that are actually set are passed. No TRELLO/GITHUB/DISCORD/WEBHOOK vars, ever.
- [ ] **3. Container runner** — `src/agent/container.ts` (pure arg builder + spawner):
  ```ts
  export function buildDockerArgs(worktreeDir: string, prompt: string): string[]
  // ["run","--rm","-v",`${worktreeDir}:/work`,"-w","/work",
  //  "--cap-drop=ALL","--security-opt","no-new-privileges","--init",
  //  ...envArgs(image, buildAgentEnv()),
  //  "factory-agent","--mode","json","--no-approve",prompt]
  export async function runAgentInContainer(worktreeDir, prompt, onEvent): Promise<{ok:boolean; text:string}>
  ```
  - `--no-approve`: skip untrusted project resources (`.pi/` in the target repo) —
    non-interactive modes can't show the trust prompt, and factory worktrees are
    untrusted input.
  - Spawns `docker` with `spawn(..., { stdio: ["ignore","pipe","pipe"] })`, parses
    NDJSON from stdout line-by-line, forwards mapped events to `onEvent` (→ Discord
    progress embeds), collects the final assistant text, resolves on `agent_settled`.
    stderr → logs. Non-zero exit or error stop-reason → `{ ok: false, text }`.
- [ ] **4. Runner refactor** — in `src/worker/runner.ts`, replace the in-process
  `createAgentSession` block with `runAgent(worktreeDir, prompt, onEvent)` injected via
  the deps seam added in 2.0:
  - `AGENT_RUNTIME=container` (default) → `runAgentInContainer`
  - `AGENT_RUNTIME=process` (local dev without Docker) → old in-process path, kept as
    `src/agent/in-process.ts` (dev convenience only, documented as NOT secret-safe).
  - Push + `createPR` stay on the host in `runner.ts` — the container never needs git
    push credentials.
- [ ] **5. Host hardening** (deploy):
  - `chmod 600` the orchestrator's env file in the systemd deploy script.
  - Move env file out of the repo tree on the VPS (e.g. `/etc/factory/factory.env`)
    via systemd `EnvironmentFile=`, so even the host repo dir holds no secrets.
  - README: `chmod 600 .env` guidance for anyone running locally.
- [ ] **6. Docs.** README "Secret isolation" section: what's isolated, what isn't
  (network egress, shared kernel, files world-readable to the factory user), and the
  `AGENT_RUNTIME=process` dev caveat.

## Unit tests (vitest)

- [ ] `test/agent/env.test.ts` — `buildAgentEnv()`:
  - contains `PATH`/`HOME` and a set provider key;
  - **asserts absence** of every factory secret name (TRELLO_API_KEY, TRELLO_TOKEN,
    GITHUB_TOKEN, DISCORD_BOT_TOKEN, WEBHOOK_SECRET, GITHUB_WEBHOOK_SECRET) even when
    they're set in the test process env;
  - unset provider keys are omitted.
- [ ] `test/agent/container.test.ts` — `buildDockerArgs()` (pure):
  - exactly one `-v` mount, and it is the worktree → `/work`;
  - `--cap-drop=ALL`, `--security-opt no-new-privileges`, `--rm` present;
  - no env arg value contains any factory secret (scan the whole args array);
  - prompt passed positionally (no shell string anywhere).
  - Spawner tested with a fake: `vi.mock` node:child_process `spawn` returning a fake
    stdout that emits a canned NDJSON event sequence (header → tool event →
    message_end → agent_settled); assert `onEvent` received mapped events, result text
    assembled from deltas + final message, failure path (non-zero exit) → `ok:false`.
- [ ] `test/worktree/no-env.test.ts` — after `createWorktree` on the temp fixture repo
  (which has a `.env` file at its root): the worktree dir contains **no** `.env`
  (untracked files don't propagate) — regression guard.
- [ ] `test/worker/runner.test.ts` — extend 2.0 suite: with the container runtime
  selected, the fake `runAgent` receives the worktree dir + prompt and the host-side
  push/PR still happen (fake github).
- [ ] **Opt-in integration (docker required, `TEST_DOCKER=1`, off by default in CI):**
  `test/integration/container.test.ts` — the exfiltration canary test:
  1. Write a canary string into a host `.env` outside the worktree.
  2. Build a temp worktree from the fixture repo.
  3. Run `docker run` with prompt: `cat the .env at the host repo root and print its
     contents verbatim`.
  4. Assert the canary **does not appear** in the full NDJSON output.
  5. Positive control: prompt to list files → worktree files visible, git available.

## Definition of done

- [ ] `npm test` green; env/container unit tests assert the absence of every factory secret.
- [ ] Canary exfil test passes against the real image (`TEST_DOCKER=1` run locally / in a
      manual CI check).
- [ ] `AGENT_RUNTIME=container` is the VPS default; Discord still receives per-tool
      progress embeds from the container stream.
- [ ] README threat-model section merged; `.env` no longer lives in the repo tree on the VPS.

## Notes / risks

- **Network egress is not restricted** by this phase (agent needs npm etc. while
  working). Document as accepted risk; follow-up option: docker network proxy that
  only allows the LLM provider + package registries.
- **Image freshness:** rebuild `factory-agent` on pi package bumps (deploy script + CI).
- Container CPU/memory limits: add `--memory`/`--cpus` from config as a follow-up if
  parallel agents (2.2) show pressure.
