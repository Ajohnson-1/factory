# Phase 2.0 — Test suite for the MVP

**Goal:** every existing module has unit tests, the ad-hoc scripts are replaced by real
tests, and CI fails on test failures. No production behavior changes — only small
testability refactors.

**Framework decision:** Vitest (ESM + TS first-class, `vi.mock` at module boundaries,
coverage built in).

## 2. Testability refactors (no behavior change)

These make the existing code unit-testable. Each is verified by its new tests.

- [x] **`src/state/store.ts`** — the killer problem: a module-level singleton opens
  `./data/factory.db` at import time. Refactor to a factory:
  ```ts
  export function createStore(dbPath: string) { /* same API, bound to dbPath */ }
  export const store = createStore(process.env.FACTORY_DB_PATH ?? path.join(cwd, "data", "factory.db"));
  ```
  Tests use `createStore(path.join(tmpdir, "test.db"))`. Production code is untouched
  because it imports the default `store`.
- [x] **`src/worker/runner.ts`** — `runCard` couples trello + github + worktree + bot +
  pi SDK. Add a deps seam:
  ```ts
  export async function runCard(cardId: string, bot: DiscordBot,
    deps: { trello?; github?; worktree?; runAgent? } = {}): Promise<void>
  ```
  defaults = current implementations. Also extract the pure
  `buildAgentPrompt(card: { name; desc }): string` and export it.
- [x] **`src/worker/worktree.ts`** — two fixes:
  - Take `repoPath` as a parameter (`createWorktree(cardId, repoPath?)`, default from
    config) so tests can point at a temp repo.
  - **Security fix found while testing:** `cardId` is interpolated into a shell string
    (`execSync(`git -C ${repoPath} worktree add ... ${branch} ...`)`). A card id like
    `x$(rm -rf ~)` is shell injection. Switch to `execFileSync("git", [...args])`
    (no shell). Add a regression test with a hostile card id.
- [x] **`src/discord/bot.ts`** — extract the pause flag into
  `setPaused(paused: boolean, dataDir?)` / `isPaused(dataDir?)` (currently
  `process.cwd()` is captured at module load), and the status text into pure
  `buildStatusText(jobs: Job[]): string`. Keep the class thin.
- [x] **`src/index.ts`** — extract `createWebhookServer(bot): http.Server` so tests can
  listen on port 0 (`server.listen(0)`) and hit it with `fetch`. `main()` just calls it.
- [x] **Move ad-hoc scripts out of `src/`:**
  - `src/dry-run.ts` → `scripts/dry-run.ts` (keep as integration smoke; add
    `"dry-run": "tsx scripts/dry-run.ts"` script).
  - `src/test-merge-webhook.ts` → delete; its assertions become
    `test/github-webhook.test.ts` (see below).

## 4. Mocking & fixture policy (keep it consistent)

- **External SDKs** (`@octokit/rest`, `discord.js`, pi SDK, `global.fetch`): mock at the
  module boundary with `vi.mock` / `vi.stubGlobal`. Never mock internal modules —
  instead use the factories/deps seams from step 2.
- **Env:** `vi.stubEnv` for anything read from `process.env`; config getters are lazy,
  so stubs work per-test.
- **Temp state:** every test that needs a DB or git repo uses
  `fs.mkdtempSync(path.join(os.tmpdir(), "factory-test-"))` in `beforeEach` and
  `rmSync` in `afterEach`. No test may touch `./data/`, the real repo, `.env`, or the
  network.
- **Git fixture helper** (`test/helpers/git.ts`): builds a bare-origin repo in a temp
  dir; reused by worktree, runner, and later reviewer tests.

## Implementation notes (choices the plan left open)

- **tsconfig:** `npm run build` stays `src/`-only. `tsconfig.test.json` adds `test/` and
  `scripts/`, run as `npm run typecheck`. Documented in the README.
- **`createWebhookServer` lives in `src/server.ts`, not `src/index.ts`** — importing
  `index.ts` executes `main()` (Discord login + worker interval), so it can never be
  imported by a test. `index.ts` is excluded from coverage; the HTTP surface is tested
  through `src/server.ts` on port 0.
- **Deps seams over internal mocks:** the default `store` is still a module singleton, so
  `handleTrelloWebhook`, `handleGitHubWebhook`, `runCard` and `createWebhookServer` accept
  an optional `deps` (`store`, `trello`, `github`, `worktree`, `runAgent`) instead of
  tests mocking internal modules. Belt and braces: `test/setup.ts` points
  `FACTORY_DB_PATH` at a per-worker temp file, so an accidental import of the default
  store cannot open `./data/factory.db`.
- **config:** `factory.webhookPort / webhookSecret / ciTimeoutMs` became getters (the
  §4 policy assumed lazy reads; they were snapshot-at-import) and numeric env falls back
  to the default for empty/non-numeric input instead of yielding `0` / `NaN`.
- **CI** runs build → typecheck → `test:coverage`, so the coverage gate is enforced and
  not just the tests.
- **Result:** 11 files, 165 tests, 93.2% lines overall; state/trello/github/discord
  areas ≥80%, `src/worker/**` 85% (queue.ts excluded by design, see below).

## Found while testing

Fixed in this phase, each with a regression test:

1. **Shell injection in `worktree.ts`** — as predicted. Every git call now goes through
   `execFileSync` with an argv array, including the `git push` that used to be an
   interpolated `execSync` in `runner.ts` (now `worktree.pushBranch`). Hostile card ids
   (`x$(touch pwned)`, `a;b`, `x;rm -rf …`) are tested for sentinel files.
2. **`git worktree add -b` failed permanently on a stale card branch** (a run killed
   before `removeWorktree`) → `-B`, so a re-trigger resets to `origin/main`.
3. **A failed `trello.addComment` after a green run flipped the job to `failed`** and
   posted a failure embed after the success embed → comment is best-effort, job stays in
   `review`.
4. **A Discord outage in the GitHub merge webhook left the HTTP request unanswered** →
   GitHub timed out and redelivered, re-sending the embed for an already-done card.
   `bot.send` is now guarded and the 200 always goes out.
5. **`github.waitForCI` called `this.ciStatus`** → broke as soon as it was detached from
   the object. Now `github.ciStatus`.
6. **The Trello client did not match Trello's documented REST API** (verified against
   developer.atlassian.com): `addComment` → `POST /1/cards/{id}/actions/comments` (was
   `…/actionsComment`, which 404s), `createWebhook` → `POST /1/webhooks` with `idModel` +
   `callbackURL` (was `POST /1/cards/{id}/webhooks` with `url`), `moveCard` → `PUT` (was
   `POST`). Card ids are `encodeURIComponent`-ed into path segments. This is the one
   place where 2.0 changed production behavior beyond testability, on the owner's call.

Still open, deliberately not fixed here:

- **Repos with no CI fail.** `getCombinedStatusForRef` reports `pending` for a head commit
  with zero statuses, so `waitForCI` burns the whole `CI_TIMEOUT_MS` and the card ends up
  `failed`. The code comment and README claimed the opposite; both now describe actual
  behaviour. Next phase should either treat "no statuses" as passed or gate on the
  workflow-runs API instead of commit statuses.
- **`moveCard` failure on the success path** still flips a green run to `failed` (same
  shape as fix 3). The card stays in Ready, so a re-trigger opens a second PR.
- **`src/worker/queue.ts` has no unit test** (0% lines; `src/worker/**` still clears 70%
  at 85%). Needs a fake-timer seam around `setInterval` plus an injectable store.
- **`DiscordBot.start()`** (slash-command registration + login) is untested; it needs a
  REST seam. `bot.ts` sits at 79% lines, the discord area at 83%.
- Card ids are unsanitised when used as path segments and refnames (`wt-<id>`,
  `factory/<id>`). No injection, but an id containing `../` could place a worktree
  outside the repo directory — sanitize at the webhook boundary.

## How to add unit tests going forward (repeat for every new phase)

1. Mirror the module path: `src/foo/bar.ts` → `test/foo/bar.test.ts`.
2. Test the **public surface** of the module; if a module is a monolith or a
   singleton, first add a factory/deps seam (2.0 pattern) — testability is a design
   requirement, not an afterthought.
3. Keep tests hermetic: temp dirs, stubbed env, mocked boundaries, no network.
4. One behavior per test; name it after the behavior ("enqueues card moved to Ready",
   "rejects tampered GitHub signature").
5. Git fixture for anything touching git; fake timers for polling loops.
6. LLM-touching scenarios get an opt-in smoke script under `scripts/` with a
   `test:*` npm script — never in the default `npm test` or CI.
