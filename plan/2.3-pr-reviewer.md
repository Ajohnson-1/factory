# Phase 2.3 — PR reviewer agent (comments on PRs after create/update)

**Goal:** when a factory PR is **created or updated**, a reviewer agent pulls it down,
reviews the diff in a disposable worktree (containerized per 2.1), and posts the
results **as PR comments** (summary + line-level comments) via the GitHub API.

**Trigger:** GitHub webhook `pull_request` event, actions `opened` + `synchronized`,
branch matching `factory/<card>`. (Today the webhook only handles `closed` + merged.)

## Flow

```
GitHub webhook (opened|synchronized, factory/* branch)
  → reviewPr(cardId, pr)                       [host, has GITHUB_TOKEN]
    → dedupe: skip if a review for this head SHA is already running/posted
    → detached worktree at the PR head SHA     (wt-review-<card>-<sha7>, no branch)
    → reviewer container (2.1 infra, role "reviewer"):
        read-only tools + web; prompt = "review diff main...HEAD"
        (worktree is checked out at head, so `git diff origin/main...HEAD` works)
    → structured output contract (reviewer must end with):
        ```review-json
        {"summary": "...", "comments": [{"path": "...", "line": 12, "body": "..."}]}
        ```
    → parse → Octokit pulls.createReview:
        event: COMMENT, body: summary, comments: line comments (≤ REVIEW_MAX_COMMENTS)
    → Discord: reviewPostedEmbed(card, prUrl, commentCount)
    → clean up review worktree
```

## Steps

- [ ] **1. `src/github/webhook.ts`** — restructure into small handlers (testable):
  - `onPrMerged(payload)` — today's merge logic, extracted as-is.
  - `onPrOpenedOrSynced(payload)` — branch match `factory/(.+)` →
    `reviewPr(cardId, payload.pull_request)` (fire-and-forget with `.catch(log)`;
    webhook always answers 200 quickly).
  - Dispatcher on `action`: `closed` → merge path; `opened`/`synchronized` → review
    path; everything else → 200 ignored.
- [ ] **2. `src/reviewer/reviewer.ts`** —
  `reviewPr(cardId: string, pr: { number, html_url, head: { ref, sha } })`:
  - dedupe check via store (`reviews` table) → skip if same `head_sha` already
    `posted` or `running`;
  - create **detached** review worktree at `head.sha` (reuse 2.0 worktree helpers,
    new `createReviewWorktree(cardId, sha)` — no branch, `worktree add --detach`);
  - run role `reviewer` via `runAgentInContainer` (registered in 2.2's role registry —
    or standalone `src/reviewer/prompt.ts` if 2.2 is skipped);
  - parse structured output; post review; store result; remove worktree (finally).
- [ ] **3. `src/github/client.ts`** — add:
  - `getPullRequest(number)` (re-check `state` right before posting; skip if closed);
  - `postReview(number, { body, comments })` →
    `rest.pulls.createReview({ event: "COMMENT", body, comments: comments.map(c =>
    ({ path: c.path, line: c.line, side: "RIGHT", body: c.body })) })`.
- [ ] **4. State** — `reviews` table: `(pr_number, card_id, head_sha, status
  [running|posted|skipped|failed], posted_at)`; store methods
  `activeReviewFor(sha)`, `markReview(...)`.
- [ ] **5. Structured-output parser** — `src/reviewer/parse.ts` (pure):
  extracts the last `review-json` fenced block; validates shape; drops comments with
  missing path/body or non-integer line; caps at `REVIEW_MAX_COMMENTS`
  (default 20); returns `{ summary, comments }` or `{ summary: rawText, comments: [] }`
  on any parse failure (review is never lost).
- [ ] **6. Discord + config** — `reviewPostedEmbed(cardName, prUrl, count)`;
  `REVIEW_MAX_COMMENTS`, optional `REVIEWER_MODEL`.
- [ ] **7. Docs** — README: what the reviewer checks (correctness, tests,
  security/secret-leaks, style), and that it re-runs on every push (`synchronized`).

## Unit tests (vitest)

- [ ] `test/github/webhook.test.ts` (extend 2.0 file) — dispatcher:
  - `opened` + factory branch → `reviewPr` called, 200 `{review: queued}`;
  - `synchronized` + factory branch → `reviewPr` called;
  - `opened` + non-factory branch → ignored;
  - `closed`+merged still routes to the merge path (regression);
  - bad signature / wrong event behavior unchanged.
  (`reviewPr` injected via deps seam or `vi.mock` of `src/reviewer/reviewer.js`.)
- [ ] `test/reviewer/parse.test.ts` — pure parser: valid block (summary + 2 comments)
  → parsed; missing block → whole text becomes summary, no comments; malformed JSON →
  graceful; comment with no path / no line / non-integer line → filtered; > cap →
  truncated to cap; multiple blocks → last one wins.
- [ ] `test/reviewer/reviewer.test.ts` — fake container runner + real temp git
  fixture (2.0 helper: base commit + head commit with a changed file):
  - happy path: detached worktree at head sha; `postReview` called with parsed
    summary + line comments; `reviews` row `posted`; worktree removed;
  - malformed agent output → summary-only review still posted;
  - **dedupe:** second `reviewPr` for same `head_sha` while `running` → skipped,
    no second container run; new sha → new run;
  - PR closed by the time we post (`getPullRequest` fake returns `closed`) → skip,
    row `skipped`;
  - container run throws → row `failed`, no review posted, worktree removed.
- [ ] `test/github/client.test.ts` (extend) — `postReview` maps to the
  `createReview` payload (event COMMENT, RIGHT side, capped comments);
  `getPullRequest` returns state.
- [ ] **Opt-in integration (docker + real GitHub test repo, `TEST_REVIEW=1`):**
  push a branch with a deliberately iffy change, open a PR, assert review comments
  appear on the PR within the timeout. Manual CI check, not default.

## Definition of done

- [ ] `npm test` green including dedupe, conflict-free worktree cleanup, and parser
      edge cases.
- [ ] Manual run: open a factory PR → reviewer comments (summary + ≥1 line comment)
      appear on the PR; push a new commit → a fresh review lands for the new head;
      Discord gets the "review posted" embed.
- [ ] No review ever blocks the webhook (200 < 1s) and none posts to a closed PR.

## Notes / risks

- **Line numbers:** the agent must reference lines in the **new** file version
  (`side: RIGHT`). Prompt states this explicitly; parser drops comments whose line
  is out of range of the file (verified against `git diff` during implementation).
- **Double-review cost:** every push re-runs the reviewer — acceptable for factory
  branches (few commits); budget guard via `REVIEWER_MODEL` if needed.
- Webhook redelivery can duplicate `opened` events → the sha-dedupe in the store is
  the idempotency guard, not webhook ordering.
