## Design decisions

1. **One bullet, not a prose paragraph.** Every entry in this section (and in
   FM-1/FM-2/FM-3 notes) is a bolded-lead-in bullet; "paragraph" in the card
   description means the paragraph-like prose body of such a bullet. Matching
   the section's prose style overrides a literal `<p>` reading.
2. **Lead-in:** `- **Acceptance trail (`self` canary #2, this card):**` —
   names the bullet per the card's "Acceptance trail" label and ties it to
   this card as canary #2 (canary #1 was `6af13b7d426ab6db2fc4b270`, the
   README Deploys section).
3. **Evidence pointers stay generic-by-location.** The implementer MUST NOT
   invent a sha or log excerpt: point at the card's comment trail by card id
   and at `<clone>/data/factory-deploy-history.jsonl` (append-only JSONL
   history, per the "self driver landed as two scripts" bullet) as the
   sources. This is honest at authoring time — the `[DEPLOY]`/`[VERIFY:PASS]`
   comments land later in this very card's run, which the pointer covers.
4. **~6 lines is a ceiling, not a target to pad.** Fit the three required
   facts in 5–7 wrapped lines; drop filler first if over.
