## 3. New file: scripts/lib/factory-platform.js (dispatch)

- `detectServiceManager({ platform = process.platform, env = process.env } = {})`
  → `'launchd'` for `darwin`, `'systemd'` for `linux`, else THROWS
  (`unsupported platform … install/status/uninstall are supported on macOS
  (launchd) and Debian/Linux (systemd user units) only`) — fail closed,
  never guess a manager. `env.FACTORY_SERVICE_MANAGER` (values
  `launchd|systemd`) overrides for test/diagnostic use.
- `assertSystemdUser({ run })` — host-fail-closed: probes
  `systemctl --user is-system-running` (read-only). Any failure (no
  manager, no user session / linger) throws naming the two remedies:
  `loginctl enable-linger factory` (§6.1) and `XDG_RUNTIME_DIR`. Every
  systemd install/status/uninstall path calls this first — a Linux host
  without a usable user bus NEVER gets a silent no-op.
- Both functions pure/injectable so the branch is unit-testable on macOS.

## 4. New file: scripts/lib/factory-platform-systemd.js (units + lifecycle)

Unit dir: `~/.config/systemd/user` (standard user unit path; overridable
in tests). Units (services + timers; one pair per satellite, daemon alone):

| Unit | Key contents |
|---|---|
| `factory-daemon.service` | `Type=simple`, `ExecStart=<node> <ROOT>/scripts/factory-daemon.js run`, `Restart=always`, `RestartSec=30`, `WorkingDirectory=<ROOT>` (§4.6 verbatim contract) |
| `factory-metrics.service` | `Type=oneshot`, Exec `factory-metrics.js once` |
| `factory-metrics.timer` | `OnBootSec=21600s OnUnitActiveSec=21600s` (6 h, launchd StartInterval equivalent), `Persistent=true` |
| `factory-sweep.service` | `Type=oneshot`, Exec `factory-sweep.js once` |
| `factory-sweep.timer` | `OnCalendar=*-*-* HH:MM:00` (default 03:15), `Persistent=true` |
| `prod-watch.service` | `Type=oneshot`, Exec `prod-watch.js once` |
| `prod-watch.timer` | `OnBootSec=300s OnUnitActiveSec=300s` (launchd StartInterval 300 equivalent) |

Env baking (card sub-step 3 + §4.6 `Environment=PATH=…~/.local/node/bin…`):
- `Environment=PATH=<dirname(nodePath)>:<HOME>/.local/node/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin` —
  the same PATH shape as `factory-daemon.js` `plistXml` (launchd's default
  PATH has no node/git/omp) with `~/.local/node/bin` baked in, so units
  start before any login shell exists.
- `EnvironmentFile=<STATE_DIR>/factory-env.conf` — installer writes this
  file from the repo `.env` (normalize: strip `export `, drop comments/
  blanks — systemd's parser rejects `export`), atomically, mode **0600**
  (secrets are never world-readable even if the checkout tree is 755).

Lifecycle (per CLI; `systemctl`/`systemd-run` via an injectable runner —
`deploy-factory.js` `defaultSystemdRun` pattern):
- `install*`: `assertSystemdUser` → write units (atomic byte-stable
  replace, 0600 env file) → `systemctl --user daemon-reload` →
  `systemctl --user enable --now <unit(s)>` (timers enabled for the
  satellites). Daemon special case (self-restart race, same argument as
  `factory-launchd.js` header): after writing, if the unit is already
  active, arm `systemd-run --user --on-active=2s systemctl --user restart
  factory-daemon.service` (D7) INSTEAD of an inline restart, so a factory
  run that installs the daemon from inside itself survives the SIGTERM
  cascade.
- `status*`: `systemctl --user show <unit> -p ActiveState -p SubState
  -p UnitFileState` (+ `ExecMainPID` for the daemon) → JSON line +
  human summary mirroring the launchd status fields (`launchd` key →
  `active`/`inactive`/`not installed`).
- `uninstall*`: `systemctl --user disable --now <unit(s)>` → remove unit
  files + env file → `daemon-reload` (unlink-before-reload order mirrors
  the launchd uninstall convergence comment: a SIGTERM cascade
  mid-uninstall converges toward "uninstalled", never a re-loading unit).

## 6. New file: scripts/probe-factory-box.js (prod-watch-from-box check)

Preflight probe FROM the box (§4.6: prod-watch from the box probes
DEPLOY_HOST — itself — over ssh with the copied private key):
- `deployConfig()` from `lib/deploy-config.js`; missing `DEPLOY_HOST` →
  exit 2 (same loud convention as prod-watch `loadCfg`).
- Builds the exact ssh command `prod-watch.js` would run
  (`ssh -i <key> -o BatchMode=yes factory@<host> <buildProbeCmd(dir)>`)
  and runs it via an injectable runner; verdicts through
  `prod-watch.js` `parseProbe` (re-exported, not re-implemented).
- Prints JSON `{ ok, probe: {kind, services, clsExit}, ssh }`; exit 0 =
  up/degraded-but-running, 1 = unreachable/unhealthy (transport or
  services), 2 = config error. Runs zero board writes → safe as an FM-6
  preflight and as the acceptance "prod-watch once" dry check.
