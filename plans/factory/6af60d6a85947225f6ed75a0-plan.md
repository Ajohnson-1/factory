# Plan — 6af60d6a85947225f6ed75a0: Keep the pending [ASK] top-of-card (ask-lift + tailless crash bookkeeping while waiting on a human)

## Goal invariant (card requirements, condensed)

Whenever a card waits on a human, the NEWEST comment is the human-facing
request itself:
- pending `[ASK]` → newest comment IS that `[ASK]`, verbatim;
- parked `needs-human` with no pending ask (stale/superseded approval, cap
  burn) → newest comment is the park comment and its FIRST line is the cap
  record + its SECOND line the human action.

Re-posting is the only lift mechanism (Trello edits do not restamp; verified
2026-11-12 per the card). Editing comments is therefore off the table.

## Design decisions (derived, not guessed)

- **D1 — what does NOT supersede for lift purposes.** `isAskPending` :342
  treats every `STAGE_VERDICT_TAGS` member (incl. `[CHECK:PASS]`/`[CHECK:FAIL]`)
  as superseding. For crash-recovery DECISIONS that stays byte-green
  (unchanged). For the LIFT invariant the card is explicit: daemon gate
  verdicts are a noise source to lift ("blocking-checks poller verdict post"
  + its test bullet), while AGENT stage verdicts supersede ("no lift for
  those"). So the lift uses a supersede set = `STAGE_VERDICT_TAGS` minus the
  two daemon gate tags. Consequence accepted deliberately: after a
  `[CHECK:FAIL]` the re-posted ask (newest date) makes `isAskPending` true
  again → crash recovery holds (zero-move conservative) until the human
  replies — same semantics a live ask already gets, and `findApprovalComment`
  accepts the reply at any date.
- **D2 — park keeps its tail** ("Resume/requeue/park posts keep the tail
  unchanged"). Tailless applies ONLY to `mode === 'hold' && holdReason ===
  'ask-pending'`: an ask-pending hold spawns no resume, so the Factor-9
  self-heal tail serves nobody while burying the ask.
- **D3 — stall-family park under a pending ask now re-posts the ask.** The
  card-13 suppression (no `[DAEMON-CRASH]` report) stays byte-green, but
  card 13's own crash comments pre-date the newest ask shape, and the
  invariant demands the ask ends top-of-card. Two existing daemon tests
  asserting `commentsWritten.length === 0` for stall parks under a pending
  ask change meaning: they become length 1 with the VERBATIM ask text (no
  crash report). This is the invariant, not a regression.
- **D4 — park stage fallback.** Park `stage` can be `''` (list name
  unreadable). Action line then reads `… to restart at the current stage.`
  Everything else byte-identical.
- **D5 — dedup is a byte compare of the newest comment against the ask text**
  (`textOf(latest) === askText`), so repeated lifts are impossible while
  nothing newer posts; Trello read-after-write lag (just-posted comment not
  yet visible to the lift's refetch) degrades to "no lift this post, next
  bookkeeping post retries" — acceptable, matches the never-reject retry class.
- **D6 — metrics denominator honesty.** A needs-human card whose latest
  comment cannot be fetched is excluded from scoring and pushed to
  `report.errors`; `ok` is `null` when the board has zero needs-human cards
  (never fabricate a green).

     untagged/`[HUMAN]` (answered) AND nothing newer carries a
